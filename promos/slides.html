The whole idea
01

robots.txt says
stay out

One Disallow line, on one path. Every crawler that reads the file obeys it.

02

An invisible link
points at it

Hidden, nofollow, out of the tab order. No reader sees it and no screen reader announces it.

03

Whatever follows
it is blocked

Getting there took ignoring an explicit instruction. That is the whole test, and it has no false positives to argue about.

Behaviour, not claims.

Invisible to
everyone real

Spliced into every front-end page before the last </body> — or placed by hand, wherever you want it.

  • A honeypot that catches people is a bug
  • Told not to follow it three separate ways
  • {{ craft.blackhole.link }} to place it yourself
On every page
<a href="/blackhole"
   title="Do NOT follow this link or you
          will be banned from this site!"
   rel="nofollow" style="display:none;"
   aria-hidden="true" tabindex="-1">&nbsp;</a>
display:none hides it from anyone reading the page
aria-hidden keeps it out of the accessibility tree
tabindex="-1" keeps it out of the tab order
title is the sentence that makes the ban defensible

The allowlist

“Googlebot”
is free to type

So anything claiming to be one is made to prove it, the way Google documents.

  • Address → hostname → back to the same address
  • Anyone can point a PTR record at googlebot.com
  • Nobody can make Google’s own DNS agree
Googlebot/2.1 crawl-66-249-66-1.googlebot.com → 66.249.66.1 VERIFIED
Googlebot/2.1 no PTR record  ·  203.0.113.7 NOT GOOGLE
Googlebot/2.1 spoofed.googlebot.com → does not resolve back NOT GOOGLE

Two DNS lookups, cached for a day, and only ever on something that already reached the trap.

The guard

Turned away
before routing

One indexed lookup at EVENT_BEFORE_REQUEST, and a banned address gets no further.

  • No templates rendered, no queries, no session
  • The session is never touched until a ban is certain
  • The check fails open — it cannot take a site down
1Is this address banned?One indexed lookup. The only cost an ordinary request pays
Everything below is skipped
2Route the requestElement lookups, matched URI rules
3Start a sessionAnd a Set-Cookie on every response with it
4Render the pageTemplates, queries, the lot

Asking “is this visitor logged in?” starts a session — and a Set-Cookie on every response is a full-page cache that never hits again. So it is asked last, not first.

Setup & console

Two commands,
then nothing

Install it, let it write the robots.txt directives, and the hidden link is already on every page.

  • Thresholds, custom paths, per-bot hit logs, redirects
  • Disable for logged-in users, email alerts, retention
  • All of it free. No editions, no licensing code
$ composer require justinholtweb/craft-blackhole
$ php craft plugin/install blackhole
$ php craft blackhole/robots/write
Added to web/robots.txt: Disallow: /blackhole
$ php craft blackhole/bots/list --status=blocked
